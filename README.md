# 秋招日程 · recruitment-timeline

秋招笔试 / 面试的时间线提醒，带一个待办清单。纯前端 + 本地零依赖小服务：不用注册、不用数据库，数据在自己的电脑上，同时写进普通文件。

> 所有数据都留在本机，没有任何请求发到外网。

## 它解决什么问题

秋招通知散落在邮件、群消息和招聘 App 里，笔试、面试、网申截止混在一起特别容易漏。这个页面把时间点收进一张时间线，用「天 / 时」倒计时盯住下一场，顺手记几条待办，并且能把日程导出到手机日历，由系统负责到点提醒。

## 功能

- **总览**：下一场大倒计时（只到天 / 时，不刷秒）、今日安排、近 7 天（含今天和下一周的同一天）、待进行、流程中、已结束。
- **日程**：阶段 网申 / 测评 / 笔试 / 面试 / Offer / 其他；状态 待进行 / 流程中 / 已结束；线上可记会议链接和**作答口令**（会议密码），线下可记地址和**通知链接**，地址和口令在卡片上都能**一键复制**；支持全天事件（网申截止这类只有日期的节点）。
- **日历**：周一起始的月视图，公司小条按公司色着色：同一家公司永远是同一个颜色，不同公司在 8 种颜色里尽量错开，超过 8 家才复用；桌面端整页不滚，只有右边「当天安排」的列表单独滚动，面试再多也不用翻整页。
- **全部事件**：按公司 / 岗位 / 备注搜索，按状态和阶段筛选，按时间正序倒序，可导出当前筛选结果。
- **TO DO**：按住事项拖动调整优先级（重要的在上），每行可编辑、可删除；勾掉即归档，归档保留 30 天（显示还剩几天可恢复），超期自动删除；归档可一键清空（先确认）；完成、删除、清空都可撤销。
- **删除都先确认**：删日程、删待办、彻底删归档、清空归档，都会先弹窗问一次。
- **提醒**：提前 0 / 15 / 30 / 60 / 120 分钟或 1 天，外加开场提醒；页面标题也会显示下一场剩余时间。
- **导出**：`.ics`（带 `VALARM`，导入手机日历后关掉网页也能提醒）、JSON 备份（日程与设置）。
- **数据**：浏览器 `localStorage` + 本地 JSON 快照 + 追加日志；损坏时自动备份原文；多标签页同步。
- **PWA**：可安装到桌面，离线可打开（需要 HTTPS 或 localhost）。
- **其他**：深浅主题（含跟随系统）、移动端底部导航、`n` 快捷键新增日程。

## 启动方式

先 `npm install`，然后按目的选一条：

| 你想做什么 | 命令 | 打开的地址 | 数据会不会写文件 |
| --- | --- | --- | --- |
| **日常使用（推荐）** | `npm run app` | http://127.0.0.1:5173 | 会：`data/` 里有 JSON 快照和日志 |
| 改前端代码，要热更新 | `npm run dev` | http://127.0.0.1:5173 | 不会，除非另开终端跑 `npm run store` |
| 只检查构建出来的静态页面 | `npm run build` + `npm run preview` | http://localhost:4173 | 不会，只有浏览器存储 |
| 跑测试 / 类型检查 | `npm test`、`npm run typecheck` | — | — |
| 重做 PWA 图标 | `npm run icons` | — | — |

直接上手就是：

```bash
npm install
npm run app
```

然后打开 **http://127.0.0.1:5173/** 。

### 这几条命令到底差在哪

- `npm run app` = `npm run build` + `node scripts/local-store.mjs`。这个本地服务同时做两件事：把 `dist/` 当静态站点托管，并提供 `/api/state` 读写接口。所以**页面和写入接口是同一个来源（5173）**，数据能直接落到 `data/`。日常用这一条。
- `npm run dev` 只是 Vite 开发服务器（热更新），没有写入接口；此时设置页会显示「未连接」，数据只进浏览器。如果想让 dev 也写文件，另开一个终端跑 `npm run store`（监听 4600，dev 会把 `/api` 代理过去）。
- `npm run preview` 只托管构建产物，同样没有 `/api`，适合临时看一眼生产构建长什么样。
- `npm run store` 单独跑本地文件服务；一般不直接用，只在配合 `npm run dev` 时用。

> 端口 / 数据目录可以改：`RT_PORT`（默认 5173）、`RT_DATA_DIR`（默认 `./data`）。
> 例：`RT_PORT=5180 RT_DATA_DIR=D:\秋招\data npm run app`。

**重启电脑后**：数据不会丢（`data/` 文件和浏览器缓存都在），但本地服务不会自己启动。重新打开终端进项目目录，跑一次 `npm run app`，再打开 http://127.0.0.1:5173/ 即可。想开机自启的话，可以把这条命令做成快捷方式放进「启动」文件夹（Win+R → `shell:startup`）。

## 数据存在哪

数据有两层，正常的路径是先写浏览器、再落文件：

1. **浏览器 `localStorage`**（按来源隔离）：`rt.v1.events`、`rt.v1.todos`、`rt.v1.settings`、`rt.v1.notified`、`rt.v1.syncedAt`。
2. **本地文件**（只有 `npm run app` 或 `npm run store` 在跑时才有）：
   - `data/recruitment-timeline.json`：全量快照，原子写入（先写 `.tmp` 再改名）。
   - `data/changes.log`：追加式 JSONL，每次写入一行，记录这次动了哪些记录。

同步规则：

- 页面启动先读文件；**文件比浏览器新，就把文件内容灌回浏览器再渲染**，所以换浏览器、清浏览器缓存都能从文件恢复。
- 每次新增 / 修改 / 删除 / 拖动排序后 400ms 合并一次写盘，并在日志里追加一条（含实体、动作、id、标题、变化字段）。
- 服务没开时照常写浏览器，下次连上会自动补写文件。
- 设置页有「立即写入文件」和「用文件覆盖浏览器」两个手动按钮。
- **覆盖前自动备份**：浏览器侧会先存一份 `rt.v1.backup.<时间>`（最多保留 3 份）；文件侧每次写入前把上一版复制成 `data/recruitment-timeline.bak.json`。万一被错误覆盖，可以从这两处找回。
- **旧数据自动迁移**：旧阶段「HR 面」并入「面试」；旧状态「已通过」→「流程中」，「未通过 / 已放弃」→「已结束」。迁移在读取时完成，不会丢记录。

### 谁覆盖谁

- **启动时**：文件比浏览器新 → 文件灌回浏览器；否则浏览器为准。
- **写盘时**：每次把浏览器当前的**全量快照**写进文件，不做两边合并；日志里记录这次 diff 出来的增减改。
- 如果浏览器和文件都被改过（例如两个浏览器各写了一次），后写的一方会整份覆盖，另一份可以从 `.bak` 或浏览器备份里找回。

几个容易踩的点：

- `http://127.0.0.1:5173` 和 `http://localhost:5173` 在浏览器眼里是**两个不同的来源**，各自有独立的 `localStorage`。选定一个用，别来回换。
- `data/` 默认在 `.gitignore` 里（避免把个人日程提交上去）；如果想用 git 备份数据，删掉那一行。
- 用静态托管部署（GitHub Pages / Netlify 等）时没有 `/api`，只有浏览器存储，也没有文件同步。
- JSON 备份只包含日程与设置，不包含待办；待办会进本地文件快照。

## 数据文件格式

快照：

```json
{
  "schemaVersion": 1,
  "revision": 3,
  "savedAt": "2026-10-21T17:45:00.792Z",
  "data": {
    "events": [],
    "todos": [
      {
        "id": "9db11df3-…",
        "text": "投递拼多多",
        "done": false,
        "createdAt": "2026-10-21T17:44:32.074Z",
        "completedAt": null,
        "order": 0
      }
    ],
    "settings": { "schemaVersion": 1, "theme": "system", "notifications": false, "defaultRemindMin": 30 }
  }
}
```

日志（一行一次写入）：

```json
{"at":"2026-10-21T17:45:00.792Z","revision":3,"changes":[{"entity":"todo","action":"add","id":"9db11df3-…","label":"投递拼多多"}]}
{"at":"2026-10-21T17:46:12.310Z","revision":4,"changes":[{"entity":"event","action":"update","id":"e1","label":"腾讯 · 面试 · 2026-10-23 14:00","fields":["status"]}]}
```

`action` 是 `add` / `update` / `delete`；`update` 会带 `fields`；文件为空时的第一次写入，会把现有记录整体记为新增。

## 提醒的能力边界

| 场景 | 行为 |
| --- | --- |
| 页面开着（前台或后台标签页） | 每 20 秒检查一次触发点，命中就发浏览器通知；需要先在设置里授权 |
| 页面关掉 | 不会提醒。用「设置 → 导出 .ics」把日程导入手机 / 系统日历，由系统负责到点提醒 |
| 触发点已过去超过 1 小时 | 不补发，避免打开页面时被过期提醒刷屏 |
| 全天事件 | 当天 09:00 提醒，提前量按分钟折算（例如提前 1 天 = 前一天 09:00） |

页面标题会跟着变，例如 `1 天 1 小时 · 【腾讯】面试 · 秋招日程`。

> 浏览器通知的可靠性边界是「页面或 Service Worker 还活着」。要保证关掉网页也能响，`.ics` + 手机日历才是可靠的那一层。

## .ics 导出

- 录入的是本地墙钟时间，导出时换算成 UTC（`...Z`），手机日历按你的时区正常显示。
- 定时事件用相对触发 `TRIGGER:-PT30M`；全天事件用绝对触发，固定在当天 09:00 前提醒。
- 严格遵守 RFC 5545：CRLF 换行、75 字节折行（不会把中文劈开）、转义 `\ ; , 换行`。
- 导出范围可选「仅待进行」或「全部事件」；全部事件页也能直接导出当前筛选结果。

## 部署与手机

- 本地日常使用：`npm run app` → `http://127.0.0.1:5173`（页面、Service Worker、通知、文件同步都可用）。
- 手机使用：需要 HTTPS 的静态托管（GitHub Pages、Netlify、Vercel 等）；局域网 `http://192.168.x.x` 不能注册 Service Worker。
- 安装：Chrome / Edge 地址栏右侧「安装」，iOS Safari「添加到主屏幕」。
- 静态托管时手机与电脑的数据不互通；想同步就复制本地 `data/` 或放进网盘。

## 边界与不做的事

- 单用户、单机数据；没有账号、云同步和多人协作（本地文件可以自己放网盘 / git）。
- 时间按设备本地时区理解（预期 Asia/Shanghai），不做多时区换算。
- 不做周期性事件、Excel / CSV 批量导入、关闭浏览器后的后台推送。
